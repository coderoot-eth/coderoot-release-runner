# Failure modes

Each failure mode gets a rule. Fail closed means: nothing published unless every check passes.
Reason codes refer to [spec.md](spec.md) §4.

| # | Failure mode | What happens | Rule |
|---|---|---|---|
| G1 | Version already on npm, **same** bytes | Publish succeeded earlier but the state report never reached the gate (crash, network) | Before publishing, read the registry. If the version exists and `dist.integrity` equals the record SHA-512: do not publish again, report `published` with the existing data. Idempotent success, not failure |
| G2 | Version already on npm, **different** bytes (npm: "You cannot publish over the previously published versions") | Someone published around the gate, or a name/version collision | Report `failed` / `integrity_mismatch`. Raise an alert to the org admin: this is a bypass signal, not a routine error |
| G3 | Duplicate dispatch, two runs at once | Gate retries a dispatch, or two dispatches race | `concurrency: publish-<package>` with no cancel-in-progress; the second run sees G1 and ends `published` without publishing |
| G4 | Retry after `failed` | Operator retries a failed release | Gate reset only ([endpoints.md](endpoints.md) §7), for `npm_error`, `runner_timeout`, `artifact_missing`, `package_missing`. Gate checks npm first (G1, G2), then starts a new attempt with a fresh claim. A re-run of the old GitHub run is refused. Other reasons are final: new submission, new approval |
| G5 | Revoked between dispatch and publish | Admin revokes while the runner is working | Re-read state immediately before `npm publish`; stop with `revoked`. If already published: the npm version stays; revocation marks the attestation and the gate never flips `revoked` back. The spec states that npm unpublish is not part of revocation |
| G6 | Artifact gone before publish | Approval arrives after the 24h upload TTL, or storage purge | Fail `artifact_missing`. The gate keeps bytes in storage through publication; the 24h TTL applies only before attach. Runner still fails closed if the download fails |
| G7 | npm outage or 5xx mid-publish | Registry unavailable | Fail `npm_error`. Do not retry inside the job past a short bounded retry. Next attempt is a gate reset (G4), which starts with the G1 check, because a 5xx can still mean the upload landed |
| G8 | GitHub outage, job never starts | Dispatch accepted, no run | Gate keeps `dispatched`. Gate marks `failed` / `runner_timeout` if no claim within 15 minutes ([spec.md](spec.md) §4), after checking npm for G1 |
| G9 | OIDC token exchange fails or expires | `id-token` request fails, or the npm token from the exchange has expired by publish time | Exchange happens inside `npm publish` itself (npm CLI does it at publish time), so keep no long step between. Failure → `npm_error`, gate reset (G4) |
| G10 | Prerelease or non-latest version | npm CLI refuses to apply `latest` implicitly when a higher version exists ("You must specify a tag using --tag", `lib/commands/publish.js`); same for prereleases | Tag rule: stable version higher than current `latest` → `latest`; prerelease → `next`; anything else (backport) → `v<major>-latest`. If the current `latest` is the placeholder version ([first-publish.md](first-publish.md)), the first real release takes `latest` whatever its kind. Rule fixed in the spec, not chosen by the submitter |
| G11 | Scoped package access | A scoped package publishes as restricted by default | Runner always passes `--access public` unless the record says otherwise. Private scoped packages are out of v1 |
| G12 | Tarball over the limit | Gate rejects uploads over 64 MiB | Nothing for the runner; the submit side already refuses. Runner still checks the size against the record |
| G13 | Placeholder or missing package | First version not created yet, or a record names the placeholder version | Missing package: `package_missing`; the runner never creates a package. Placeholder version: `placeholder_version` in `resolve`, before any npm check, so it never reaches G2 and never raises a bypass alert |
| G14 | Runner reports nothing at all | Job crashed before any report | Same as G8: gate timeout. Gate cross-checks the registry before marking `failed`, to catch G1 |
| G15 | Silent failure nobody sees | `failed` releases pile up unnoticed | Every `failed` notifies the org admin; `integrity_mismatch` and `runner_timeout` also post to the operations alert channel (gate side) |
